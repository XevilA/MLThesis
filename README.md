# คู่มืออธิบายโครงสร้างไฟล์และหลักการทำงานของระบบ

โปรเจกต์นี้คือการสร้าง AI มาทำหน้าที่เป็น "ออดิท" คอยตรวจสอบความถูกต้องของข้อมูลการปล่อยคาร์บอนในโรงงาน เนื่องจากข้อมูลที่เก็บจากเซ็นเซอร์มักจะมีปัญหาเน็ตหลุด ข้อมูลแหว่ง หรือแย่กว่านั้นคือมีการแอบแก้ตัวเลขให้ดูดีเกินจริง

ระบบของเราเลยแก้ปัญหานี้ด้วยสเต็ป 2 ขั้นตอนง่ายๆ:
1. **ซ่อมข้อมูลก่อน:** ถ้าช่วงไหนเซ็นเซอร์หลุด AI ตัวแรกจะเข้ามาประเมินและเติมตัวเลขให้สมบูรณ์
2. **สแกนจับผิด:** พอข้อมูลครบแล้ว AI ตัวที่สองจะมาเช็คว่า "ค่าไฟ" กับ "ของที่ผลิตได้" มันสอดคล้องกันไหม ถ้าผลิตของได้เยอะแต่ค่าไฟนิดเดียว ระบบจะจับโป๊ะทันที

## 📂 อธิบายไฟล์ในโปรเจกต์ (แต่ละตัวทำหน้าที่อะไรบ้าง?)

เพื่อความเข้าใจง่าย ผมขอแบ่งไฟล์โค้ดทั้งหมดออกเป็น 3 กลุ่มหลักๆ ครับ

### กลุ่มที่ 1: ตัวจำลองโรงงาน (เอาไว้สร้างข้อมูลมาทดสอบ AI)
เนื่องจากเราไม่สามารถไปหาข้อมูลที่มีการ "ตั้งใจโกง" จากโรงงานจริงๆ มาทดสอบได้ เราเลยต้องเขียนโค้ดจำลองสภาพแวดล้อมของโรงงานขึ้นมาเอง

* **`config.py`**: ไฟล์ตั้งค่าศูนย์กลาง สมมติว่าโรงงานตั้งอยู่ที่ระยอง มีเครื่องจักร CNC กี่ตัว สเปกแผงโซลาร์เซลล์เป็นยังไง เราจะมากำหนดค่าตัวเลขทั้งหมดไว้ที่ไฟล์นี้ครับ
* **`factory_model.py`**: โค้ดสำหรับคำนวณ "ค่าไฟ" ของโรงงาน โดยคิดรวมตั้งแต่แอร์ แสงสว่าง ไปจนถึงไฟที่ใช้ตอนเดินเครื่องจักร
* **`production_model.py`**: โค้ดตารางการทำงานของพนักงาน จำลองว่ามีกะเช้า กะบ่าย มีทำโอที มีหยุดเสาร์อาทิตย์และวันหยุดนักขัตฤกษ์ รวมถึงจังหวะที่เครื่องจักรเสียกะทันหันด้วย
* **`solar_model.py`**: โค้ดคำนวณไฟที่ผลิตได้จากหลังคาโซลาร์เซลล์ โดยดึงข้อมูลสภาพอากาศ แดด และอุณหภูมิมาคำนวณ
* **`fault_injection.py`**: "ตัวป่วนข้อมูล" โค้ดตัวนี้จะทำหน้าที่จำลองเหตุการณ์เซ็นเซอร์พัง เน็ตหลุด หรือจำลองการจงใจแก้ตัวเลข (โกงค่าไฟ/ยอดผลิต) เพื่อสร้างโจทย์ไปท้าทาย AI
* **`validation.py`**: ตัวรีเช็คความสมจริง เอาไว้ตรวจว่าข้อมูลจำลองที่เราสร้างขึ้นมาทั้งหมดเนี่ย มันดูสมเหตุสมผลตามสถิติของโรงงานในไทยจริงๆ ใช่ไหม
* **`main.py`**: ไฟล์หลักของกลุ่มนี้ แค่กดรันไฟล์นี้ มันจะไปสั่งงานไฟล์ข้างบนทั้งหมดให้ช่วยกันปั๊มข้อมูลจำลองออกมาเป็นไฟล์นำไปใช้งานต่อได้เลย

### กลุ่มที่ 2: ส่วนสร้างและสอน AI (เทรนโมเดล)
* **`train_bilstm.py`**: โค้ดสอน AI ตัวที่ 1 (BiLSTM) เราสอนให้มันรู้วิธีเดาและเติมตัวเลขเวลาเซ็นเซอร์ดับให้เนียนที่สุด โดยดูบริบทจากยอดผลิตและแสงแดด
* **`train_autoencoder.py`**: โค้ดสอน AI ตัวที่ 2 (Autoencoder) เราสอนให้มันจำพฤติกรรมปกติของโรงงาน ถ้ายอดผลิตกับค่าไฟเริ่มไม่สมเหตุสมผล มันจะแจ้งเตือนว่าข้อมูลผิดปกติทันที

### กลุ่มที่ 3: ระบบใช้งานจริงแบบครบวงจร
* **`run_pipeline.py`**: ไฟล์แพ็กเกจรวมฮิตสำหรับใช้งานจริง พอกดรันปุ๊บ มันจะรับข้อมูลดิบเข้ามา -> ส่งให้ AI ตัวแรกซ่อมส่วนที่พัง (ใช้ Monte Carlo Dropout ประเมินความมั่นใจ) -> ส่งต่อให้ AI ตัวที่สองจับผิดการโกง -> ขีดเส้นจับผิดแบบไดนามิก (EVT/POT Threshold) -> แล้วสรุปผลคะแนนความแม่นยำออกมาเป็น Multi-Seed Benchmark
* **`run_all_baseline.py`**: โค้ดทดสอบเทียบชั้น (Benchmark) เอาโมเดลของเราไปชกกับคู่แข่ง (Z-Score, Isolation Forest) ด้วยกติกาเดียวกัน (Blind Unsupervised) แบบไม่มีใครโกงข้อสอบ
* **`evt_threshold.py`**: ตัวช่วยคำนวณสถิติ Extreme Value Theory (EVT) เพื่อหาจุดตัด Threshold อัตโนมัติจากข้อมูลปกติ

## 🎯 ระดับการแจ้งเตือน (เวลา AI จับผิดได้)
เวลาระบบเจอความผิดปกติ มันไม่ได้แค่บอกว่า "ผิด" แต่จะช่วยแยกเกรดความรุนแรงให้ด้วยครับ
* **Marginal (เตือนเบาๆ):** ข้อมูลเริ่มเพี้ยนไปจากปกตินิดหน่อย อาจจะแค่จังหวะเปิด/ปิดเครื่องจักร
* **Structural (เตือนระดับกลาง):** ข้อมูลเริ่มขัดแย้งกันอย่างเห็นได้ชัด น่าจะมีเซ็นเซอร์พังหรือคีย์ตัวเลขผิด
* **Critical (เตือนภัยร้ายแรง):** ข้อมูลขัดแย้งกับหลักความจริงแบบสุดๆ (เช่น เครื่องจักรวิ่งเต็มสปีดแต่ค่าไฟเป็นศูนย์) อันนี้ฟันธงได้เลยว่ามีโอกาสทุจริตข้อมูลสูงมาก

## 📈 ผลการทดสอบโมเดลล่าสุด (Latest Benchmark Results)

จากการทดสอบรันไปป์ไลน์ทั้งหมด (รวมถึงการทำ Monte Carlo Dropout และ EVT/POT Calibration) ผ่านการทดสอบความเสถียร 5 รอบ (Multi-Seed Benchmark: 42, 43, 44, 45, 46) ได้ผลลัพธ์ดังนี้:

### 1. การประเมินความไม่แน่นอนของการเติมข้อมูล (Monte Carlo Dropout - Stage 1)
การเติมข้อมูลที่แหว่งด้วย BiLSTM แบบเดาซ้ำๆ 50 ครั้ง (K=50) พบว่า:
* **PICP (Prediction Interval Coverage Probability):** `29.95%` (ค่าจริงตกลงในกรอบความเชื่อมั่น 95%)
* **ACE (Average Coverage Error):** `-65.05%`

### 2. ขีดเส้นจับผิดด้วยคณิตศาสตร์ (EVT/POT Calibration - Stage 2)
โมเดลไม่ได้สุ่มเดาเส้นขีดตายตัว แต่คำนวณจาก Clean Data:
* **Shape Parameter (Weibull Tail):** $\xi \approx -0.068$ (โมเดลเข้าใจว่าเพดานการใช้ไฟของเครื่องจักรมีอยู่จริงตามหลักฟิสิกส์)
* **Dynamic Threshold (q=0.001):** `0.003479` (เส้นจับผิดที่ยอมให้เกิด False Positive แค่ 0.1%)

### 3. ประสิทธิภาพการจับโกง (5-Seed Stability)
ตัวเลขผลลัพธ์ที่เสถียรมากๆ ยืนยันว่าโมเดลไม่ได้ฟลุ๊ค:
* **Precision:** `0.2177 ± 0.0004`
* **Recall:** `0.0944 ± 0.0000`
* **F1-Score:** `0.1317 ± 0.0001`
